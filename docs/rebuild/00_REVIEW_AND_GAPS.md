# 00 · 入仓审查与调整记录

## 审查结论

入仓前，EvoNext 只有简版架构、兼容、路线、运维和当前验收说明；对话交付的完整 PRD、领域合同、接口/工作台、迁移、63 项验收和独立实施任务书没有在仓库中。本次将其主体补入 `docs/rebuild/`，保留编号与合成例子，并修正与后来已确认决定冲突的内容。

原文件 SHA-256 记录在 `SOURCE_MANIFEST.json`，用于说明来源，不冒充当前修订文件的摘要。不是把原压缩包原封不动上传：公开仓库不保存私有源码、真实轨迹、内部地址、敏感审计材料。

## 已处理的冲突

| 问题 | 本次决定 |
|---|---|
| 旧稿优先评估 PG 替换 Mongo，最新决定保留三种存储 | 删除默认迁库方向，固定 Mongo 事实、MinIO 字节、PG 控制记录 |
| 旧稿将 Workshop/Runtime 全部排除出新仓库 | 新仓库拥有一份清晰的候选核心与消费合同；外部执行器仍是 adapter，不复制旧实现 |
| 扁平 Python 文件将 API、数据、调用、Worker 放在一起 | 分 app/contracts/evidence/operations/providers/compat/skills/runtime，旧内部路径移除而非保留多套实现 |
| 只有 Langfuse 打点，没有收费调用恢复 | 增加发送前 PG 回执、响应先保存、未知不自动重发、请求预算；不声称 exactly-once |
| Prompt、模型与业务规则缺少运行身份 | 外置受控策略包，依赖内容哈希、StrictUndefined、冻结配置；不再建独立 Prompt 后台 |
| Skill 学习后是否直接生效不清楚 | 保存只得到 candidate；显式导出固定版本；实验授权与独立采用分开 |
| Runtime 是否等于手机回滚不清楚 | 当前只冻结计划/上下文、校验授权与回执；真实恢复必须验证状态并产生新轨迹 |
| 目标规格与工程进度混在一起 | 本目录是目标，docs/ACCEPTANCE.md 是实测；ROADMAP 只保留下一顺位 |

## AIHOT/OpenClaw 借鉴范围

详细映射见 [设计依据](../adr/0001-aihot-openclaw.md)。采集、预筛、评分、聚合、校准、共享读取和架构约束都有去向，不将新闻 0–100 分、双评分均值、来源热度或自动合并直接当 GUI 业务规则。OpenClaw 的 Skill 格式、固定会话快照、Runtime/传输分离与版本恢复可借鉴；即时学习生效、自动读取任意 home skill 和全套插件服务不是本项目默认策略。

## 尚未完成

现役完整评分器/首错诊断、模型驱动的有界学习和复核、自动失败聚合、人审/Case 页面、真机恢复、独立收益验证、正式 Dataset publisher、在线全量双向同步均未因文档入仓而完成。本轮提供可测试的基础与接口，不创建空成功响应或付费后台循环。

原始证据存储的无损交换保持；后续查询投影、媒体完整性、来源级授权与生产恢复仍需真实环境验收。保存 JSON 字符串的快照底座不是完整检索方案，也不意味着要把 Mongo 再换成 PG。
