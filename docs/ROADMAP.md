## 演进主线：Benchmark 牵引的 Skill 收益闭环

**先证明有用，再自动提炼，再自动选择，最后形成受控持续进化。** 近期积累两类可复用知识：避坑，以及入口与路径。北极星是在固定 Executor、同等信息权限与预算、可比起态下，提高未参与开发实例的成功率，或在成功率与安全性不退化的前提下降低成本。Skill 数量、生成通过率、检索命中率和 Reviewer 认可率只是过程指标。

新增进化能力归 EvoNext；EvoLoop 保留现役执行和历史证据入口。复用合同、数据与回归，消费者替换验收后再退役旧入口，每个领域保持一个写入权威。Workshop 接收已分流的操作方法问题；工具、环境、Executor、偏好 Memory、权重和数据问题仍归各自领域。

```text
轨迹 / 人工纠正 / 使用反馈 → 冻结 Evidence → Evaluation / 按需 Diagnosis
→ Review 选择干预 → 查找已有 Skill → 定向提炼或修补 → 不可变候选
→ 冻结实验 → 现有 Runtime / Executor → 新 Trial → 独立 Evaluation
→ 限定采用 / 修补 / 回退 Raw / 停用 → 封存本轮，反馈进入下一轮
```

### 与原里程碑的关系

M0–M4 保留产品覆盖范围；R0–R5 是其中能力进化的推进门槛，不能理解成第二套独立排期。

| 原范围 | 本轮明确的顺位 |
|---|---|
| M0/M1a 底座 | 复用候选版本、CAS、diff、Undo、精确导出与 Runtime 合同，不重做编辑器 |
| M1b 工作台 | 保留 Review/Case、人工纠正、评估接入的在途收口；先完成 R0 所需读回路径，其余功能不必全部完成才实验 |
| M2 真实修复实验 | 承载 R0/R1；纠正原任务和迁移到新实例分别验收。可靠 Fork 可用就续跑，否则从干净初态重跑 |
| M3 资产与自进化 | R2/R3/R4/R5 按门槛展开；冻结成员、来源许可、污染隔离提前到 R0，正式训练与数据发布仍在 M3 |
| M4 生产替换 | 独立的运维与切换门槛，不是 R0/R1 的前置条件，也不因 Skill 实验通过自动启动 |

当前按 **R0 准备阶段**推进，不宣称已完成真实对照。实现证据只记在 [ACCEPTANCE](ACCEPTANCE.md)；本路线中的门槛均是计划。旧 PR 编号是历史上下文，不作为当前分支已合入或验收通过的证明。

### R0–R5：按证据门槛推进

| 阶段 | 最小交付 | 进入下一阶段的条件 |
|---|---|---|
| R0 · 建立实验基线 | 冻结样本、复位方法、实际上下文回执、独立 Outcome、12 次 smoke | 全部成员可追溯；失败/unknown 不丢；在途版本固定；从工作台读回输入与新证据 |
| R1 · 证明指南有价值 | 少量同源指南、固定适用性选择、None/Raw/Skill 配对对照 | 未参与开发实例上出现可重复避坑或效率收益，无关键边界退化；未达预设阈值则继续取证或停止 |
| R2 · 自动提炼与修补 | 有界 learner/reviewer、Patch 优先、No Change、版本与来源回执 | 自动产物经独立执行验证；修补保留旧分支；报告无人修改与人工辅助结果及完整成本 |
| R3 · 自动选择与拒绝 | 检索、当前状态适用性、0/1 选择、精确版本渐进加载 | 正例选对、近似负例拒绝；与 R1 固定选择基线比较，解释自动端到端收益 |
| R4 · 受控持续学习 | 事件触发、去重、自动草稿、受控试验、限定采用 | 至少两轮真实闭环；预算、暂停、版本冻结和副作用边界生效 |
| R5 · 规模化维护 | 分范围监测、回退、合并、瘦身、归档、升级回归 | 维护成本与负迁移受控；模型/App 变化后重验范围；经验可停用、收益可复现 |

R1 的人工审核指南标记 `assisted`，只证明知识形态的价值上界，不计入自动学习成果。若它也无收益，先检查问题选择、表达与消费者，不扩大生成器。

R2 先检查已有方法，再决定 `Patch / Create / Merge / No Change / Needs Evidence`。每次只改有证据支持的知识增量；作者与复核共享预算、修补次数有上限，缺证、重复候选、来回振荡或预算耗尽即停止。格式通过与作者自评不能替代执行收益。

R3 将语义相关性和当前 App、页面、目标、参数、前提的适用性分开；允许不选，初期最多选一个。先用已有索引或简单元数据；只有检索被证明确为瓶颈，才增加复杂检索设施。

R4 的触发可来自失败诊断、纠正续跑、新入口、绕路或重复错误。作者只读证据、写候选；执行与采用独立授权，不默认扩大范围。

### Benchmark 与对照协议

自己的授权轨迹负责问题真实性，成功、失败、unknown 都保留。按任务族与来源 lineage 隔离用途；重试、重复上传和同任务不同版本不当独立案例。

| 用途 | 使用约束 |
|---|---|
| 学习来源 | 可用于提炼与修补；记录来源、许可和可见证据窗口 |
| 开发验证集 | 可反复调试生成、选择与执行；明确已暴露 |
| 回归集 | 检查旧能力与负例；可用于改进，但不能再称未见测试 |
| 保留确认集 | 当轮冻结方法后才运行；反馈用于修补后转为已暴露材料，下一轮另留实例 |

按原讨论，AndroidWorld 是首个公开在线对照的接入目标，MobileWorld 后置为补充。接入前核对上游固定版本、许可证、媒体、初始化及验收器可用性；此处是选择顺序，不宣称适配已实现。公开环境用于可复现锚点，不能替代目标业务 App 验证；换参数/随机种子主要证明近迁移，不等于跨 App 泛化。

先选 1–2 个低风险、可复位且有独立验收方法的任务族，覆盖避坑和入口路径：

- 首轮：**4 个任务/起态单元 × None/Raw/Skill = 12 次 smoke rollout**。覆盖典型任务、不同起态或参数、已到目标、相似但不适用。用于工程打通和局部信号，不证明普遍有效。
- 稳定后：**2 个任务族 × 每族 4 单元 × 3 组 × 2 重复 = 48 次 rollout**，只有 8 个案例单元；不包含学习采集、提炼、复核与环境检查成本。
- None：同一 Executor，无历史经验；Raw：同批授权来源按冻结规则形成的精简材料；Skill：同源冻结指南。Raw 的抽取/摘要策略、人工加工与成本均记录，不能暗中增加答案或替任一组补充未来证据。
- 三组从可比起态重新执行，历史失败不能充当 None。模型、工具、预算上限、任务判据相同，记录实际使用量；Raw/Skill 采用相同的来源权限与可见窗口。现有 raw 合同有决策点截止约束，若不足以表达实验来源，先显式补合同，不能静默放宽。
- v1 之后主比较 None/v1/v2，并周期性保留 Raw。选择方式单独固定，手选收益不等于自动召回收益。

### 资产、消费与采用边界

Skill 以 Markdown 为主，粒度为意图稳定、起止明确、价值可独立验证的子流程。正文包含适用/不适用目标、必要输入、前提、入口与关键状态、当前界面下的策略、陷阱、恢复、停止与完成检查。参考文件按需读；尚不需要独立召回的片段不拆成新 Skill，不先建层级组合引擎。Experience 暂为学习证据摘要和引用，不建独立数据库。

内容版本、执行评价、采用决定分开。采用范围至少绑定 **Skill revision × 模型/配置 × 任务范围 × App/环境 × 验收证据**；新 revision 不继承旧版结论。不用单个 `verified=true` 表达有效性，发布/启用不替代当次执行授权，训练资格也不随采用自动获得。

先接现有可运行 Executor 的固定 guidance/context，不以前置 Planner 建设阻塞实验。若已有双层架构，Planner 接收策略与子目标，Executor 接收当前阶段的入口、约束和停止条件，避免重复全文注入。回执记录实际送达的内容、引用与 hash；送达不能证明消费者正确使用，仍须对照执行证据。

Fork 恢复由执行端验证账号、App、输入数据、页面及副作用状态；截图相似、步骤号或请求 hash 都不是等价证明。不能可靠恢复时采用干净初态全量重跑；改变动作后执行新后缀。外部副作用结果未知时先核对，不自动重放。归档阻止新使用，在途取消仍由 Runtime 负责。

### 证据等级与每轮报告

| 等级 | 可以作出的结论 |
|---|---|
| L1 · 静态合同 | 格式、路径、参数、来源绑定、权限和版本正确 |
| L2 · 历史支持 | 方法及适用范围有证据，无明显无据扩写 |
| L3 · 真实执行 | 在明确环境完成任务或修复已知失败 |
| L4 · 保留任务对照 | 未参与开发实例相对基线有可重复净收益 |

L1/L2 支持保存候选和受控试验，不能替代 L3/L4。分别报告“资产是否有效”和“自动提炼/修补/召回流程是否稳定有效”。成功修复原失败只算纠错证据，不自动升级迁移结论。

每轮固定报告以下结果，判据来自原用户目标与冻结任务合同，待测 Skill 不得改写：

1. 成功、失败、unknown 完整分母；逐案例赢/平/输/不可比。另列计划、阻塞、已派发、已回流、可判定数量，不以删除缺失运行美化结果。
2. 重复错误：预定义触发点，分别统计是否到达、是否复现、最终是否成功；提前失败不算避坑成功。
3. 导航效率：入口到达率、步骤、耗时、Token；全体结果与双方均成功的配对成本同时报告。
4. 负迁移：基线成功而候选失败、越权、错误结束或成本显著增加，逐项定位关键分歧。
5. 完整成本：生成、复核、检索、执行、纠错、未知收费与人工分钟数；重复次数和独立案例数分开。

失败归因区分未提炼、内容错误、漏召回、误召回、Executor 未有效使用、工具/环境故障与缺证，不一律追加 Skill 规则。

### 首批工作包与本次补充

以下将对话中的 A/B/C 工作包落实为可交接的交付边界；它们是下一步工作，**本次文档入仓不将其标为完成**。

| 工作包 | 交付物与唯一职责 | 验收与原合同对应 |
|---|---|---|
| A · 冻结第一套实验 | 实验用例负责清单；Evidence 负责来源。固定任务族、学习/开发/回归/保留用途、4 个 smoke 单元、起态复位、独立判据、三组定义与预算 | 任一案例能回答输入、可学来源、复位方式、评价者、比较目标。沿用架构 §9.2–9.4、AX-08/09，不要求先建完整 Dataset 平台 |
| B · 一个消费者与回流 | Runtime 负责执行，Evaluation 负责独立判定，Workbench 提供对比入口：固定上下文 → Executor → 新 Trial → Outcome → 对比 | API/CLI 和页面引用同一成员；读回实际输入、精确 Skill revision、来源及新轨迹。沿用 AC-056–060、AX-08–12；prepare-trial 与 binding 通过不算已执行 |
| C · 第一张完整差异表 | 实验用例汇总，Review 记录后续决定；12 次运行及失败/缺失均留存 | 展示赢平输、unknown、负迁移、成本与关键分歧，只选一个有证据的下一轮改进点。R0 完成不自动算 R1 收益成立 |

**本次补充的实施约束：**

- **运行前预注册门槛。** A 中填明主要指标、允许退化界限、最小有意义收益、重复次数、人工与模型预算、停止条件及负责人；目前不虚构统一数值。未定门槛只能探索，不能事后挑阈值宣布采用。小样本报告逐对结果及不确定性，不声称显著泛化。
- **顺序和污染控制。** 各组交错或随机执行并记录顺序，每次核验复位；清除跨 Trial 的会话经验、缓存和账号状态残留。学习来源、当前任务观察、验收器隐藏信息分别限权；评价者不接收候选自评或组别提示。授权来源不等于来源内任意指令可信。
- **复现身份完整。** 清单固定代码/策略版本、环境/验收器版本、请求和实际响应模型、参数、来源 revision、context hash、案例/组别/repetition 与 Trial 映射。模型/环境漂移则另记分层或判不可比；在途不替换 latest。不把这些控制字段写回源轨迹。
- **失效与撤权可追踪。** 来源撤权、App/模型升级或关键反例触发适用范围复审；停止新的采用/消费，保留合规的审计引用，在途动作按 Runtime 规则收束。内容回退、采用撤回和设备状态回滚分别记录。
- **接口和状态只补断点。** Mongo/MinIO/PG 权威不变，Runtime 只依赖 contracts.skills，收费调用走 providers.gateway 与持久回执。复用现有 Review/Case、Evaluation 和 Celery，不创建第二个 Run Store、评分器或调度器。

连续两轮有界实验没有增加收益证据，就暂停扩量；Raw 更便宜且同样有效时允许回退；模型升级后不再有增益的指南允许停用。每个新需求必须回答：观察到什么问题、最低成本基线、冻结案例和指标、唯一负责模块以及停止条件。

当前后置：通用 DemoParser、手机端 Workshop UI、Skill 专属数据库/微服务控制面、通用脚本/宏编译、复杂组合与检索设施，以及以模型训练替代经验收益验证。稳定高频路径的加速仅在收益明确后交由 Runtime 单独评估。

## M1b：可替代日常数据工作台

完整使用链为：导入/回流 → 搜索筛选 → 固定版本及步骤/模块证据 → 任务/步骤标签与注释 → 原图 bbox/坐标及动作修订 → 人工结论/Case → 保存 → 刷新与重启读回 → 导出。

必须补齐而非静默遗漏：

| 能力 | 验收要点 |
|---|---|
| 单条/批量导入与回流 | 逐项接收回执、失败/取消/重试分母、固定媒体来源；部分写入不伪装全部成功 |
| 搜索/标签/集合 | task/app/source/time/status/step 条件、分页、批量标签、集合冻结；动态查询不是 DatasetVersion |
| 轨迹/模块证据 | 提案、规范化动作、实际 dispatch、回执、后态、用户改令及缺证各自定位 |
| 版本与编辑 | 原始只读；修订追加，CAS 冲突明确；历史 Case 回到原版本，不跟着 latest 漂移 |
| 人工审阅与 Case | 人机结论分离；任务/步骤标签、评论、认领、分配、批量分诊、归档/恢复、纠正审计 |
| 长轨迹 | 200/2000 步导航、图片懒加载、取消旧请求、保护未提交草稿、固定深链接 |
| 导入/导出运营 | 大文件有界、对象完整性、来源隔离、取消及核对恢复；可恢复不等于外部副作用回滚 |

存储与 UI 独立实现，但事实归属不复制；现有使用中能力应有“替换/适配/暂缓/明确退役”的去向台账。

## M2：可信评估与一个真实修复实验

Evaluation：单条/冻结批次共用 Spec/Run/Attempt/Record；Outcome、Step/Span、控制专项、Agentic 取证保留不同业务语义。执行报错、证据不足、未评估、不适用和业务失败分开。未知不自动重跑；机器结果不覆盖人审。

2026-11-08 增补授权按完整平台轨迹搭建评估/诊断。优先完整轨迹输入、Fast Judge、实际图片送达与有界 Investigator，业务结果持久化暂缓扩展。Outcome 可早停，过程诊断仍可独立启动。完整轨迹与首轮图片预算的关系见 [架构 §9.6](rebuild/03_ARCHITECTURE.md#96-完整轨迹评估与按需诊断)，实际交付见 ACCEPTANCE。

Diagnosis：允许首个有证据的错误区间、多因、替代解释和 unknown；区分 first wrong action 与 first causal divergence。Case 审核决定修复路线，可选 tool/runtime/rule/memory/skill/weight/environment/safety/data/clarification，而不是所有错误都写成 Skill 或训练样本。

真实闭环：冻结失败 → 审核定位 → 选择最小干预 → 验证手机相关状态恢复 → Teacher continuation 产生新 trial → 独立评价 → 与 baseline 比较。手机不能任意回滚；恢复可能失败。改变动作后不可复制历史后缀冒充新轨迹。执行重试与评分重试不同。

实验机配置、三条执行路径、回流对账和首轮放量条件见[目标架构第 9 节](rebuild/03_ARCHITECTURE.md#9-实验机执行路径与数据回流目标设计)。

先用一个有代表性的任务连通；无收益、unknown 或不可比也是合法实验结论。统一记录完整分母、证据覆盖、模型调用及未知成本。

### M1b 到 M2 的交付顺序（计划）

| 顺序 | 工作台交付 | 验收后再推进 |
|---|---|---|
| 1 · 收口 Review/Case | 从轨迹的具体步骤提出问题，从待审列表打开同一 Case。任何值得纠正的步骤均可建 Case；任务整体失败留在 Evaluation / Diagnosis。 | 先收口 PR #3 的隔离 PG 并发与浏览器写入读回，再验步骤必填、跨步纠正被拒、同一步多个候选逐项审核、草稿恢复和冲突比较（AC-014、016、017、019）。 |
| 2 · 人工标注与步骤纠正 | 在动作前截图分别框出原动作指向的区域与建议目标，按证据补充正确动作、理由或成对偏好。保存一次审核修订，供诊断、定位评测、回归、监督学习或偏好学习引用。 | 浏览器验收只画一个框也可提交、缩放后两类框均能准确读回、只给正确动作、明确偏好、两种动作等价、缺证与误派发。按各用途核对依据和缺项（RV-02/03、DS-05）。 |
| 3 · 接入机器评估与诊断 | 在同一工作区对照固定的旧来源结果与 EvoNext 独立 Outcome，再按需调查首错。审核员可采纳、驳回、要求补证，定位到另一步时关联该步独立的 Case，已有人工修订始终可查。 | 独立评分输入隔离已有判决；验证引用可回到同一来源，并覆盖只有终态、首错未知的例子（AC-016、022、050）。 |
| 并行 · Local Runtime；随后汇合 | 固定决策位置和恢复条件；由操作者选择干预并单独申请实验。从 Case 读回新 Trial、实际后态和独立评分，再决定采用、补证或停止。 | 起态不可比时记录阻塞；可比时核对新执行后缀，配对报告改善、退化、无变化与不可判。分别报告操作员处理用时与实际修复收益（AC-056–060）。 |

首轮以一个 GUI 动作纠正贯通 API、CLI 和浏览器。训练资格审核、正式数据发布沿用 M3 顺位，DAL 继续暂缓。交互、偏好预览与反例见[工作台规格 §4.3](rebuild/04_API_AND_WORKBENCH.md#review-correction)。
