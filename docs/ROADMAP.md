完整需求与原验收编号已在 [rebuild](rebuild/README.md) 入仓。本文件只维护交付顺位，不重写另一份功能总表。

## M1b：可替代日常数据工作台

完整使用链为：导入/回流 → 搜索筛选 → 固定版本及步骤/模块证据 → 任务/步骤标签与注释 → 原图 bbox/坐标及动作修订 → 人工结论/Case → 保存 → 刷新与重启读回 → 导出。

必须补齐而非静默遗漏：

| 能力 | 验收要点 |
|---|---|
| 单条/批量导入与回流 | 逐项接收回执、失败/取消/重试分母、固定媒体来源；部分写入不伪装全部成功 |
| 搜索/标签/集合 | task/app/source/time/status/step 条件、分页、批量标签、集合冻结；动态查询不是 DatasetVersion |
| 轨迹/模块证据 | 提案、规范化动作、实际 dispatch、回执、后态、用户改令及缺证各自定位 |
| 版本与编辑 | 原始只读；修订追加，CAS 冲突明确；历史 Case 回到原版本，不跟着 latest 漂移 |
| 人工审阅与 Case | 人机结论分离；任务/步骤标签、评论、认领、分配、批量分诊、归档/恢复、纠正审计 |
| 长轨迹 | 200/2000 步导航、图片懒加载、取消旧请求、保护未提交草稿、固定深链接 |
| 导入/导出运营 | 大文件有界、对象完整性、来源隔离、取消及核对恢复；可恢复不等于外部副作用回滚 |

存储与 UI 独立实现，但事实归属不复制；现有使用中能力应有“替换/适配/暂缓/明确退役”的去向台账。

## M2：可信评估与一个真实修复实验

Evaluation：单条/冻结批次共用 Spec/Run/Attempt/Record；Outcome、Step/Span、控制专项、Agentic 取证保留不同业务语义。执行报错、证据不足、未评估、不适用和业务失败分开。未知不自动重跑；机器结果不覆盖人审。

Diagnosis：允许首个有证据的错误区间、多因、替代解释和 unknown；区分 first wrong action 与 first causal divergence。Case 审核决定修复路线，可选 tool/runtime/rule/memory/skill/weight/environment/safety/data/clarification，而不是所有错误都写成 Skill 或训练样本。

真实闭环：冻结失败 → 审核定位 → 选择最小干预 → 验证手机相关状态恢复 → Teacher continuation 产生新 trial → 独立评价 → 与 baseline 比较。手机不能任意回滚；恢复可能失败。改变动作后不可复制历史后缀冒充新轨迹。执行重试与评分重试不同。

先用一个有代表性的任务连通；无收益、unknown 或不可比也是合法实验结论。统一记录完整分母、证据覆盖、模型调用及未知成本。

## M3：资产与自进化

| 能力 | 边界 |
|---|---|
| Skill / Raw Memory | 固定候选版本、实际消费记录、反馈与 Undo；先对比 none/raw/skill，不继承旧独立生产链 |
| Dataset / Governance | 训练/开发/回归用途、family/lineage 去重与污染隔离、固定成员及 manifest；do_not_train 不因导出解除 |
| 训练信号 | SFT/DPO/步骤/恢复/安全信号保留源失败、老师纠正、可见上下文截止和独立验证；不泄漏未来证据 |
| 模型/Prompt/Harness 实验 | 有效配置冻结、声明版本与实际响应版本分开、配对比较、改善/退化/缺失同报 |
| 外部执行 | local 以设备为单位，云真机可按 batch；两者共享回流合同，不强塞同一种调度单位。Local Device Queue 控制面 MVP 见 [ADR-004](adr/0004-local-device-execution-queue.md) 与 [Codex 工作包](work-packages/local-device-queue-mvp.md)；真实 Driver 接入和设备恢复另行验收 |
| 训练/部署协作 | 交付版本化数据包与收据，不在 Flywheel 内重建训练集群、算力调度或发布系统 |
| 分布/需求/成本分析 | 来源、时间窗、需求分母与样本暴露明确；检索 Top-K 不是能力成功率 |
| 专项算法接入 | 匹配、VQA、Planner/GUI 交接等保留专业输出，不把它们压成一个 pass 布尔值 |

## M4：生产替换

在真实目标环境完成访问/来源权限、备份恢复、增量同步/删除、计数与媒体守恒、外部消费者、队列故障、负载和运维验收。切换使用单一写入权威；回退必须保留新系统已接收的新数据，不能简单指回旧服务然后丢掉新写入。

**只读工作台阶段完成（2026-11-07）**。以下四块为已完成范围与保留差异，不是继续迁移的执行授权；验收与旧版差异清单以 ACCEPTANCE.md 为准：

1. 显示设置：已接入任务/采集时间、来源评估和现有步骤证据字段开关、本地偏好及恢复默认。时间默认隐藏，其余已接入字段默认显示。
2. 时间线：已接入明确重试步骤的图片堆叠、单组/全部展开与收起、当前组高亮和 Grid 可见项导航；缺图/人工步骤保持独立，页面与窗口有界。用户所指的色块选择尚未确认，保留为未迁项，不将静态图例冒称筛选能力。
3. 图片 marker：已接入 BBox、批量动作顺序/序号、同点合并与多端点箭头，大小图/全屏共用 SVG 投影；按用户确认，BBox 与动作默认均为 0–1000，保留显式像素/未声明选项。旧 BBox 的识别/转换交给治理管道，不继续扩展前端兼容分支；其余旧提案格式留作未迁项，不执行历史 code。
4. 追踪与其余只读信息：已接入跟随步骤的打点原文面板、嵌套字段搜索和来源追踪引用入口；真实 Langfuse 模块日志仍待明确来源引用及服务接通。运行事件专用视图、其他未适配的来源记录与编辑/审核留待独立工作包，不复制旧写入路径。


已完成本地真实离线包经 API 的读取展示，以及按旧 workbench 浏览合同重建的只读界面验证；当前范围和未验边界见 ACCEPTANCE.md。编辑/审核仍按独立切片接入。
